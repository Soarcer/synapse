# Ship Synapse v0.1.0 — Design Spec

**Date:** 2026-03-11
**Author:** Bernhard (with Claude)
**Status:** Draft

## Problem Statement

Synapse is a fully functional agent monitoring dashboard with a VS Code extension, server, and React frontend. It has 34 test files, comprehensive docs, and a working build pipeline. But it has never been publicly released. The codebase carries AGPL licensing, an enterprise /ee directory, inconsistent version numbers, and no publishing infrastructure.

**Goal:** Ship Synapse as a public, MIT-licensed open-source project with two distribution channels:

1. VS Code extension (Marketplace + Open VSX + GitHub Releases)
2. npm CLI (`npx @synapse-ai/cli`) for terminal Claude Code users

**Non-goals:**

- Revenue or monetization (fame/recognition is the primary goal)
- Multi-provider support (Claude-focused)
- OpenClaw plugin in v0.1.0 (deferred, but validated during this exercise)

## Key Decisions

| Decision        | Choice                                                 | Rationale                                                                                  |
| --------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| License         | MIT                                                    | Maximum community goodwill. Same as OpenClaw (closest peer). No friction for contributors. |
| Distribution    | VS Code Marketplace + Open VSX + GitHub Releases + npm | Maximum reach across all channels.                                                         |
| Testing bar     | E2E + VS Code extension tests                          | High confidence before going public.                                                       |
| Enterprise /ee  | Remove entirely                                        | Pure MIT, no dual-license complexity.                                                      |
| OpenClaw plugin | Defer from v0.1.0                                      | Validate it works, but don't include in initial release.                                   |
| Version         | v0.1.0                                                 | "Early but usable." All packages normalized to same version.                               |
| CLI experience  | `npx @synapse-ai/cli`                                  | Zero-install. Runs server, opens browser dashboard.                                        |

## Architecture

### What Ships

```
Published Packages (npm):
  @synapse-ai/core    v0.1.0  — Types, Zod schemas, format utils
  @synapse-ai/server  v0.1.0  — Express + SQLite + WebSocket server
  @synapse-ai/cli     v0.1.0  — CLI entry point (bundles server + dashboard)

Published Extension:
  synapse-vscode      v0.1.0  — VS Code Marketplace + Open VSX

GitHub Release:
  synapse-vscode-0.1.0.vsix   — Downloadable artifact
  Source code archives         — Auto-generated by GitHub
```

### What Does NOT Ship

```
  @synapse-ai/openclaw   — Deferred to v0.1.1+
  @synapse-ai/dashboard  — Private, bundled into CLI and extension (not published separately)
  /ee directory           — Removed entirely
```

### Track 2 — Testing

**VS Code Extension Integration Tests:**

- Framework: `@vscode/test-electron`
- Test file: `apps/vscode/src/test/suite/extension.test.ts`
- Coverage:
  - Extension activates without errors
  - `synapse.startServer` starts the embedded Express server
  - `synapse.stopServer` stops the server gracefully
  - `synapse.openDashboard` creates a webview panel
  - `synapse.configureHooks` writes correct config to `.claude/settings.json`
  - Server health check (`GET /api/health`) responds after startup
  - WebSocket connection establishes
  - Graceful shutdown (no orphaned node processes)

**Expanded E2E (Playwright):**

- Existing: 3 specs (analytics-api, analytics-overview, analytics-tabs)
- Add:
  - Dashboard loads and renders React Flow graph
  - Simulated session events appear as nodes (use `simulate_session.ts` fixture)
  - Keyboard shortcuts: T (tool log), L (layout), Space (pause), / (search)
  - Graph search finds nodes by name
  - Snapshot export (E) produces valid JSON, import (I) restores state

**Performance & Memory Leak Audit (time-boxed: 4 hours):**

Acceptance criteria — must pass to ship:

- Server heap usage plateaus (does not grow >20% over 30 minutes of continuous events)
- Dashboard renders 100+ nodes at >30fps
- No WebSocket connection leaks after 10 connect/disconnect cycles
- CLI/extension shutdown leaves no orphaned node processes
- Dashboard bundle size <5MB (gzipped)

Findings that don't meet thresholds are filed as GitHub issues for post-v0.1.0, not blockers.

- Server long-running stability test:
  - Run server for extended period with continuous simulated events
  - Monitor Node.js heap usage (`process.memoryUsage()`) over time — heap should plateau, not grow linearly
  - Check for WebSocket connection leaks (disconnected clients still held in memory)
  - Check for SQLite/sql.js memory growth (query result caching, unbounded DB growth)
  - Verify event listener cleanup on session end (EventEmitter leak detection)
- Dashboard performance audit:
  - React Flow rendering with 100+ nodes — measure frame rate, identify jank
  - Zustand store subscription leaks (components mounting/unmounting)
  - Check for detached DOM nodes using Chrome DevTools Memory panel
  - Verify `useEffect` cleanup functions run on unmount (WebSocket listeners, intervals, timeouts)
  - Bundle size analysis (`vite-plugin-visualizer`) — identify unexpectedly large chunks
- VS Code extension:
  - Webview disposal — verify server shuts down when panel closes
  - Extension deactivation — no orphaned processes after VS Code closes
  - Memory usage of embedded server within VS Code's Node.js process
- CLI:
  - Graceful shutdown on SIGINT/SIGTERM — no zombie processes
  - Port cleanup — verify port is released after shutdown
  - File handle cleanup (SQLite DB, log files)
- Tooling:
  - Add `--inspect` flag support to CLI/server for heap profiling
  - Consider `clinic.js` (Doctor + Flame) for automated performance analysis
  - Add a stress test script: `scripts/stress_test.ts` that floods the server with events and monitors memory

**OpenClaw Plugin Smoke Test:**

- Run `pnpm --filter @synapse-ai/openclaw simulate`
- Verify events flow through to dashboard
- Document pass/fail — not blocking v0.1.0

### Track 3 — Ship Infrastructure

**CLI Build-Out (`@synapse-ai/cli`):**

NOTE: The CLI already has subcommands implemented (`start`, `stop`, `status`, `hook`, `unhook`, `help` in `packages/cli/src/cli.ts`). The main work is **bundling and packaging**, not command logic.

- Bundling strategy (the key technical challenge):
  1. esbuild inlines `@synapse-ai/server` source into CLI bundle (same as VS Code extension approach)
  2. Dashboard static files: pre-build dashboard via Vite, then copy `dist/` into CLI's `resources/dashboard/` directory
  3. CLI esbuild config copies dashboard resources into the final bundle directory
  4. `files` field in `package.json` must include `bin/`, `dist/`, AND `resources/`
  5. At runtime, CLI serves dashboard static files via Express `express.static()`
  6. sql.js (not better-sqlite3) — same asm.js redirect trick as the VS Code extension esbuild config
- Existing subcommands to keep as-is: `start`, `stop`, `status`, `hook`, `unhook`, `help`
- Add: auto-open browser on `start` (`open` / `xdg-open` / `start` based on platform)
- Bin entry: `@synapse-ai/cli` -> `bin/synapse.mjs`

**Publishing Pipeline (GitHub Actions):**

CI Workflow (`.github/workflows/ci.yml`) — already exists, needs updating:

- Trigger: push to main, all PRs (already configured)
- Steps: install deps, lint, typecheck, test (vitest), build all packages
- Update: add Node 22 to matrix (currently only Node 20)
- Update: add Playwright E2E step after build

Release Workflow (`.github/workflows/release.yml`):

- Trigger: push tag `v*`
- Steps:
  1. Install deps
  2. Lint + typecheck
  3. Run full test suite (vitest + Playwright)
  4. Build all packages
  5. Publish `@synapse-ai/core`, `@synapse-ai/server`, `@synapse-ai/cli` to npm
  6. Build `.vsix`
  7. Publish to VS Code Marketplace (`vsce publish`)
  8. Publish to Open VSX (`ovsx publish`)
  9. Create GitHub Release with `.vsix` artifact
- Secrets needed: `NPM_TOKEN`, `VSCE_PAT`, `OVSX_TOKEN`
- Build order constraint: core -> server -> dashboard -> cli -> vscode (dependency chain)

**GitHub Repo Polish:**

- Repository description: "Real-time agent monitoring dashboard for Claude Code"
- Topics: `ai`, `agent`, `monitoring`, `claude`, `vscode-extension`, `developer-tools`
- README badges: license (MIT), npm version, VS Code Marketplace version, CI status
- `CONTRIBUTING.md`: fork, branch, PR, tests must pass, MIT license for all contributions
- Issue templates: bug report, feature request
- `.github/FUNDING.yml` if desired (GitHub Sponsors, Ko-fi, etc.)

## Success Criteria

1. `npx @synapse-ai/cli` starts server + opens dashboard on a fresh machine with Node 20+
2. VS Code extension installs from Marketplace and shows agent graph for an active Claude Code session
3. All tests pass (vitest unit + Playwright E2E + VS Code extension integration)
4. `git tag v0.1.0 && git push --tags` triggers automated release to npm + Marketplace + Open VSX + GitHub
5. README clearly explains what Synapse does, how to install, and how to contribute
6. LICENSE file is MIT with correct copyright

## Prerequisites (check before starting implementation)

1. **npm scope `@synapse-ai`** — verify you own this organization on npmjs.com. If not, register it or choose an alternative scope. None of the scoped packages can publish without this.
2. **VS Code Marketplace publisher** — create a publisher account and Personal Access Token (PAT) from Azure DevOps.
3. **Open VSX namespace** — register on open-vsx.org.
4. **Playwright test infrastructure** — confirm existing E2E specs have server startup/teardown wired up in `playwright.config.ts`. New specs will reuse this.

## Risks & Mitigations

| Risk                                                        | Mitigation                                                                                                |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| VS Code Marketplace review rejection                        | Follow all marketplace guidelines; test on multiple OS before submitting                                  |
| npm package name `@synapse-ai/cli` taken                    | Check availability early; have backup names ready                                                         |
| CLI bundle too large                                        | Dashboard static files add size; consider lazy download on first run if >20MB                             |
| Breaking changes to Claude Code hooks API                   | Hook scripts are simple POST relays; easy to update. Pin to known hook event schema.                      |
| Open VSX publishing delays                                  | Open VSX reviews can take time; publish to Marketplace first                                              |
| `@vscode/test-electron` flaky on CI                         | Budget extra time; these tests are notoriously platform-sensitive. Consider running only on ubuntu in CI. |
| VS Code Marketplace first-time review                       | Can take 1-5 business days with possible iterations. Submit early.                                        |
| npm scope `@synapse-ai` unavailable                         | Check availability as first step. Have backup: `synapse-ai` (unscoped) or `@synapse-dash`                 |
| openclaw `better-sqlite3` breaks `pnpm install` on clean CI | Exclude openclaw from workspace or make its deps optional                                                 |
