The Problem

When Claude Code invokes AskUserQuestion, it blocks waiting for terminal input. If you're away from your desk — cooking, on the couch, walking around — the agent sits idle. Default timeout: 30 minutes of wasted time.

What if you could answer from your phone?

The Solution

Synapse intercepts permission requests via Claude Code Hooks, renders interactive question cards on a web dashboard accessible from any device on the LAN, and relays answers back through the deny + message protocol.

Step 1

Intercept

Claude Code's PermissionRequest hook POSTs to Synapse's hook server. The HTTP response is held open — Claude blocks until we respond.

Step 2

Broadcast

The server broadcasts the question via WebSocket to all connected dashboards. The raw tool_input (with questions, options, multiSelect) is included for rich rendering.

Step 3

Interact

The dashboard renders an interactive card with tappable options, radio/checkbox selection, tab navigation for multi-question prompts, and a live countdown timer.

Step 4

Relay

User taps "Send Answer". The server wraps answers as deny + message and resolves the held HTTP response. Claude receives the answers and continues.

Why This Matters

This is the first hooks-based solution that relays structured answers back to Claude — not just allow/deny, but actual user selections from multi-option questions. Combined with ngrok, this works from anywhere in the world, not just your LAN.

The Deny + Message Trick

Claude Code's PermissionRequest hook has a critical asymmetry that makes this whole system possible.

The Asymmetry

FieldOn "allow"On "deny"
decision.behavior Tool proceeds normally Tool is blocked
decision.message IGNORED — not forwarded FORWARDED to Claude as context

The only way to pass information back to Claude through the hook system is to deny the tool call with a message. Claude receives the denial, reads the message containing the user's answers, and continues without re-asking.

Wire Format

Click each step to see the exact JSON payloads.

1 Claude → Hook Server (PermissionRequest) ▼

Claude Code POSTs to /api/hooks/permission and blocks.

json // POST /api/hooks/permission { "tool_name": "AskUserQuestion", "tool_input": { "questions": [ { "question": "Pick your favorite color:", "header": "Color", "options": [ { "label": "Blue", "description": "Cool and calm" }, { "label": "Green", "description": "Fresh and natural" }, { "label": "Orange", "description": "Warm and energetic" } ], "multiSelect": false } ] }, "session_id": "abc-123" }
2 Server → Dashboard (WebSocket broadcast) ▼

Server broadcasts to all connected dashboard clients, including the raw tool_input for rich rendering.

json { "type": "pendingPermission", "data": { "id": "a1b2c3d4-...", "tool_name": "AskUserQuestion", "tool_input_preview": "{\"questions\":[{\"question\":\"Pick...", "tool_input_raw": { /* full questions object */ }, "createdAt": 1741795200000, "expiresAt": 1741797000000 } }
3 Dashboard → Server (PUT decision + answers) ▼

Dashboard sends the user's selections. Note behavior: "allow" — the server overrides this to "deny".

json // PUT /api/permissions/:id/decision { "behavior": "allow", "answers": { "Pick your favorite color:": "Green" } }
4 Server → Claude Code (hook response — the trick) ▼

Server resolves the held HTTP response with deny + message. Claude sees the message.

json { "hookSpecificOutput": { "hookEventName": "PermissionRequest", "decision": { "behavior": "deny", // overridden from "allow"! "message": "The user answered this question remotely via the Synapse dashboard. Do NOT re-ask this question. Use these answers and continue: Q: Pick your favorite color: A: Green" } } }

Result

Claude receives the denial message, sees "Green" was selected, and continues without re-asking. The deny+message instruction explicitly tells Claude to treat the answers as user input.

Card State Machine

PENDING

Live countdown, interactive options. User can tap radio/checkbox buttons to select answers. "Send Answer" is disabled until all questions have at least one selection.

RESOLVED

User tapped "Send Answer" (answers relayed) or "Deny" (plain deny). Card is removed from pending, added to resolved history (max 50).

EXPIRED

Timer hit 0:00. Server auto-denies with timeout message. Card shows amber state with "Dismiss" button.

iOS Safari Fix

Mobile permission cards were invisible due to CSS containment issues.

The Bug

iOS Safari creates a containing block when html/body have position: fixed + overflow: hidden. This traps all position: fixed children inside the viewport frame, making permission cards invisible when they overflow.

The Fix

createPortal() renders PermissionPanel directly into document.body, escaping all clipping ancestors.

tsx function MobilePermissionPortal() { return createPortal(<PermissionPanel mobile />, document.body); }

The Landscape

Official

Anthropic Remote Control

Official solution via claude remote-control. Routes through Anthropic's cloud. Full bidirectional control but requires Max plan ($100-200/mo), single session only, no visualization.

Community

claude-remote-approver

60 lines of bash + ntfy.sh push notifications. Approve/deny only. No web UI, no dashboard, no AskUserQuestion relay. Simple but limited.

SDK-based

AgentDeck

Cloudflare tunnel + xterm.js terminal on phone. One-command setup. Uses Claude Code SDK (not hooks). Live terminal, push notifications, but no node graph or analytics.

Native App

CCPocket

Native mobile app for Claude Code + Codex. WebSocket bridge. Batch approval, syntax-highlighted diffs, push notifications. Uses SDK/stdio, not hooks.

Monitoring

claude-code-dashboard / Agent Monitor

Monitoring-only dashboards. Track sessions, tool usage, costs, subagents. No permission approval, no answer relay. Hooks-based observability.

Unique

Synapse

Only hooks-based tool that relays structured answers back to Claude. Combines visual node graph + permission approval + monitoring in one tool. LAN-only, zero cloud deps, VS Code extension, free.

Key Insight

GitHub Issue #15400 reports that AskUserQuestion unexpectedly triggers PermissionRequest hooks — which is exactly the behavior Synapse exploits. No other hooks-based project has leveraged this for bidirectional Q&A. There's even a separate Issue #12605 requesting dedicated AskUserQuestion hook support — Synapse already solves this.
