Playbook: Add cursor-based pagination to REST endpoint
✨ Key Lesson — Why This Playbook Scored 94/100
This session followed the optimal pattern: Plan → Implement → Verify → Refine. By starting in Plan Mode, Claude explored the existing codebase and proposed an approach that reused existing utilities. This prevented reinventing pagination logic and kept the implementation consistent with the rest of the codebase. The verification step caught edge cases before they became bugs.
⚠️ Common Mistakes to Avoid
  • Skipping the plan step — Jumping straight to implementation without analyzing existing patterns leads to inconsistent code and missed reuse opportunities.
  • Not specifying pagination type — Vague prompts like "add pagination" leave Claude guessing between offset-based, cursor-based, or page-based approaches.
  • Forgetting to test edge cases — Pagination has tricky edges (empty results, last page, invalid cursors). Always verify with real queries.
