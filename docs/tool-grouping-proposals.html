Tool Call Grouping Proposals

Three approaches to replace individual tool nodes with compact, interactive group visualizations. Click any tool in the demos below to see the detail panel.

Proposal 1: Pill Grid

Replace individual tool nodes with a compact grid of interactive pills embedded in a summary node. The parent agent node shows a collapsed chip; clicking expands into the full pill grid.

Strengths

  • Extremely space-efficient — 48 tools in the area of ~4 old nodes
  • Status visible at a glance (color + icon)
  • Collapsed state shows summary chip with mini status dots
  • Natural grid scales: auto-fills columns as count grows
  • Click any pill for full detail panel
  • Familiar pattern (badges, chips) — low learning curve

Trade-offs

  • Loses spatial relationship (edges) to the tool nodes
  • Duration only visible on hover or in detail — not in the pill itself at scale
  • Tool-to-child-agent edges need special handling (Task tool)
  • At 48+ tools, grid becomes tall; may need internal scroll
Implementation: In React Flow, the pill grid would be a single custom node type (toolGridNode) positioned where the old stacked tools were. The agent node's tool count badge becomes clickable to expand/collapse. Clicking a pill dispatches setSelectedNodeId(toolUseId) which opens the existing detail panel. The grid node's dimensions auto-size and dagre accounts for it as one node instead of N.

Proposal 2: Timeline Strip

Replace tool nodes with a Gantt-style horizontal bar where each segment is proportional to the tool's execution duration. Shows temporal flow, relative cost, and bottlenecks at a glance.

Execution Timeline

Strengths

  • Shows execution order and relative duration — immediately spot slow calls
  • Color-coded by tool type makes patterns obvious (all Reads, all Bashes)
  • Single compact bar replaces N nodes; fixed height regardless of tool count
  • Grouped-by-type variant shows parallel lanes like a Gantt chart
  • Hover tooltips and click-to-detail maintain full inspectability
  • Great for performance analysis — where is the agent spending time?

Trade-offs

  • Very thin segments for fast tools (<100ms) — hard to click
  • Duration isn't always meaningful (some tools are I/O bound)
  • Doesn't show success/error as clearly (need secondary indicator)
  • Grouped variant takes more vertical space than single bar
  • Minimum segment width needed for usability stretches time accuracy
Implementation: A custom React Flow node (toolTimelineNode) renders a flex-based bar. Segment widths are Math.max(duration / totalDuration * 100, 3)% with a 3% minimum for clickability. The node is attached via a single edge from the agent. Clicking a segment dispatches the same detail panel action. The grouped variant uses Object.groupBy(tools, t => t.toolName) to create swim lanes.

Proposal 3: Heatmap Matrix

A matrix where rows are tool types and columns are sequential calls. Cell color encodes status (success/error), cell opacity encodes duration (darker = longer). Reveals patterns in tool usage and failure clustering.

Strengths

  • Reveals patterns: "Read always succeeds, Bash fails 40% of the time"
  • Duration intensity shows bottlenecks per tool type
  • Extremely dense — 32+ tools in a compact grid
  • Rows grouped by type give semantic structure
  • Color scales provide overview even without reading text
  • Hybrid mode encodes TWO dimensions (status + duration) simultaneously

Trade-offs

  • Higher learning curve — users must understand the matrix encoding
  • Small cells (28px) limit label text; depends on hover tooltips
  • Empty cells when tool types have unequal call counts (sparse matrix)
  • Loses temporal ordering between different tool types
  • Color-blind users may struggle with status+intensity encoding
Implementation: A custom React Flow node (toolHeatmapNode) groups tool calls by toolName and renders a CSS Grid. Cell background uses hsla() with hue from status (160 = teal/success, 0 = red/error) and alpha from duration / maxDuration. Clicking a cell dispatches setSelectedNodeId. The node width adapts to the max column count.

Recommendation: These three proposals are not mutually exclusive. The Pill Grid could serve as the default collapsed view (replaces the current stacked tools), while Timeline Strip and Heatmap Matrix could be available as alternate "lens" modes toggled via the existing keyboard shortcuts or a dropdown on the grid node header. This gives users the quick overview (pills), the performance view (timeline), and the debugging view (heatmap) — all sharing the same click-to-detail interaction.
